Two state machines

Do not collapse these into one.

Donation status

The overall food request:

REPORTED → MATCHING → NOTIFIED → ACCEPTED → PICKUP_IN_PROGRESS → PICKED_UP → DELIVERED

Defined in lib/donations/status.ts.

Rescue assignment status

One volunteer attempt, which may be retried:

OFFERED → ACCEPTED → EN_ROUTE_TO_PICKUP → ARRIVED_AT_PICKUP → PICKED_UP → EN_ROUTE_TO_NGO → ARRIVED_AT_NGO → DELIVERED

Defined in lib/rescue/status.ts.

Interview insight: a donation is the business object; an assignment is a delivery attempt. Separating them lets the system expire or reject one volunteer offer and create another without losing the donation's identity or history.

Placement-ready answer

Say this, then go deeper.

“Food Rescue Network is a role-based Next.js App Router application. A donor submits surplus food through a route handler; a domain service validates the workflow and uses a Prisma transaction to create the donation, rank nearby NGOs, write status history, notify candidates, and queue live events. NGO acceptance is guarded by a conditional database update, so the first valid claimant wins. A separate rescue-assignment state machine handles volunteer offers, expiry, GPS geofences, OTP pickup, and NGO delivery confirmation. The database is authoritative; Ably and the SSE stream keep screens current.”
