# Mission: Explain and defend Food Rescue Network in placement interviews

## Why

Placements are approaching, and the user wants enough project fluency to explain this application clearly, trace its important workflows, answer design and debugging questions, and make small safe changes with confidence.

## Success looks like

- Give a two-minute architecture walkthrough without reading the repository.
- Trace a donation from the donor request to NGO matching, volunteer delivery, and final confirmation.
- Explain why the project uses separate donation and rescue-assignment state machines.
- Locate the right route handler, domain service, schema, worker, and test when investigating a feature.
- Discuss authentication, transactions, retries, realtime delivery, and failure cases in interview language.

## Constraints

- Teach in short, project-specific lessons with retrieval practice.
- Prefer the repository's actual code and high-trust primary documentation.
- Build confidence progressively; do not require memorising every UI component or dependency.

## Out of scope

- Exhaustively learning every visual component before understanding the domain flow.
- General placement preparation unrelated to this project unless the user asks for it.
