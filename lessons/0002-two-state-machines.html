Lesson 02 · placement prep · 10 minutes

Two state machines, one rescue

Learn to separate the lifecycle of the food request from the lifecycle of one volunteer delivery attempt. This is the domain-model explanation interviewers are likely to probe.

Mission link

Being able to name the state owner and guard makes debugging and architecture answers much sharper.

The distinction

Aggregate vs attempt.

Donation = overall request

REPORTED → MATCHING → NOTIFIED → ACCEPTED → PICKUP_IN_PROGRESS → PICKED_UP → DELIVERED

Question answered: “What is happening to the food donation?”

Assignment = one attempt

OFFERED → ACCEPTED → EN_ROUTE_TO_PICKUP → ARRIVED_AT_PICKUP → PICKED_UP → EN_ROUTE_TO_NGO → ARRIVED_AT_NGO → DELIVERED

Question answered: “What is happening to this volunteer route?”

Why split them? An offer can expire, be rejected, or fail. The system can create a new assignment attempt for the same donation without resetting the donation or erasing the history of the first attempt.

Trace the important triggers

Read the left side, then the right.

  1. NGO accepts a matchrespondToMatchCandidate() moves the donation from NOTIFIED to ACCEPTED. No volunteer assignment exists yet.
  2. Volunteer accepts an offeracceptVolunteerOffer() records the acceptance event and immediately leaves the assignment in EN_ROUTE_TO_PICKUP. The trip has started, but the food has not been collected, so the donation remains ACCEPTED.
  3. Volunteer reaches pickuprecordVolunteerLocation() uses trusted GPS accuracy and dwell time to move the assignment to ARRIVED_AT_PICKUP. It does not prove handoff.
  4. Donor OTP is verifiedverifyPickupOtpForVolunteer() records the handoff and moves the assignment toward the NGO. The donation advances through PICKUP_IN_PROGRESS and PICKED_UP in the same transaction.
  5. NGO confirms receiptconfirmRescueDelivery() requires ARRIVED_AT_NGO, then marks both the assignment and the donation delivered.

Two code rules protect the graph

State transitions are executable policy.

Donation guard

assertTransition() checks the allowed next donation status and throws INVALID_STATUS_TRANSITION for a jump.

Assignment guard

assertRescueAssignmentTransition() protects the delivery attempt and keeps terminal outcomes terminal.

Placement phrasing: “The state machines turn domain policy into code. Instead of trusting the UI to send sensible next statuses, the service validates every transition at the server boundary.”
